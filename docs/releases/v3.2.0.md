# MITI v3.2.0 — Run with pixi or Docker, and foxglove_bridge beside MITI

MITI 3.2 starts with one command on any machine and can take foxglove_bridge off the robot.

## Start MITI

**pixi** (no Node.js or ROS install needed):

```bash
pixi run miti        # http://<this machine>:3000
pixi run miti 8080   # another port
```

The first run installs Node.js and the npm packages and builds MITI; later runs start in about a second unless the source changed. Linux (x86-64, ARM64) and macOS (Apple silicon).

**Docker Compose**, as a service that comes back after a restart:

```bash
docker compose up -d
```

## foxglove_bridge beside MITI

Run foxglove_bridge on the MITI machine instead of the robot. It joins the robot's ROS 2 network over DDS and subscribes only to the topics someone is viewing; the robot just publishes, and the subscribing, encoding and per-browser WebSocket traffic happen on the MITI machine.

```bash
pixi run -e humble miti-bridge          # MITI + bridge (use -e jazzy for a Jazzy robot)
docker compose --profile bridge up -d   # the same with Docker (Linux, host networking)
```

- **Settings** in `.env` (see `.env.example`): `ROS_DISTRO` (Docker, default `humble`), `ROS_DOMAIN_ID`, `RMW_IMPLEMENTATION` (Fast DDS or Cyclone DDS), `BRIDGE_TOPIC_WHITELIST`, `BRIDGE_PORT`, `BRIDGE_SEND_BUFFER_LIMIT`.
- **Message types**: the standard packages are included (common_interfaces, tf2, nav2, map, moveit, foxglove, control and vision messages). Put the robot's own message packages in `ros/overlay/src` and build them with `pixi run -e humble build-msgs`; the Docker image builds them automatically.
- **Match the robot's distro.** Humble and Jazzy nodes do not discover each other reliably.
- **Raw images are still large.** Over DDS a raw 1280×720 camera reached about 2.5 frames per second on a test network while joint states, TF and odometry arrived in full; use `/compressed` image topics. `ros/cyclonedds.xml` and the deployment guide cover socket buffers for Wi-Fi.

## Connecting

Without `NEXT_PUBLIC_BRIDGE_URL`, MITI now connects to port 8765 on the machine it was opened from, so `http://<miti-host>:3000` reaches a bridge running beside it from any computer. The connection settings still change the address, and the choice is remembered per browser.

## Docker fixes

- `NEXT_PUBLIC_BRIDGE_URL` is a build argument; set at run time, as before, it had no effect.
- The image installs exactly the locked packages (`npm ci` with `package-lock.json`) and uses Node.js 22.

Details: [docs/DEPLOYMENT.md](https://github.com/hiran-t/MITI/blob/main/docs/DEPLOYMENT.md).
