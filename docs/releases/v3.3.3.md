# MITI v3.3.3 — Windows bridge fix and a quiet install

## foxglove_bridge on Windows

- **The bridge no longer exits at start with `0xC0000135`** (DLL not found). RoboStack's Windows package installs `foxglove.dll` and `foxglove_cpp_shared.dll` in `Library\lib`, where Windows does not look for them; the bridge script now adds that folder to `PATH`. The harmless `WinError 1314` warning about the log symlink is silenced too.
- **MITI and the bridge always agree on the port.** On Windows a port forwarded for one address (for example by `netsh interface portproxy`) could look free to MITI's launcher while the bridge script saw it taken, so MITI was told one port and the bridge used the next. The launcher now also checks whether something answers on the port, and the bridge uses exactly the port MITI was told.

## A quiet install

`pixi run miti` and `npm ci` no longer print warnings:

- Jest 30 with jsdom 29 replaces Jest 29, removing `inflight`, `glob@7`, `abab`, `domexception` and `whatwg-encoding`.
- ESLint 10 with a flat config (`eslint.config.mjs`) replaces ESLint 8 and `eslint-config-next`, keeping the Next.js core-web-vitals rules and the Rules of Hooks. `npm run lint` now runs `eslint .`.
- `uuid`, `three-mesh-bvh` and `test-exclude` are pinned to supported versions with npm `overrides`, and the browser data (`caniuse-lite`) is current.
- The npm update notice and the Next.js telemetry notice no longer appear in pixi output.

Next.js, React, three.js and the other runtime packages are unchanged. `ws` is now a direct dev dependency, because the load harness in `scripts/` uses it.
