# MITI v3.1.0 — Foxglove-style Image panel and a smooth UI under heavy data

MITI 3.1 turns the camera panel into an Image panel like Foxglove's, with 3D topics drawn over the camera image, and keeps the whole UI smooth while a robot streams raw cameras, lidar, TF and logs.

## Image panel

- **Overlays**: pick a Calibration topic (Auto uses `<image dir>/camera_info`) and turn on topics in the panel's Topics section. Point clouds, laser scans, occupancy grids and costmaps, poses, paths, markers and robot models are drawn over the image, projected through the camera's intrinsics and placed with TF.
  - **Sync timestamps** uses TF at the image's timestamp; if that is not available yet, the latest transform is used and a notice says so.
  - Without calibration or TF the image still shows, with a message explaining what is missing.
- **Color mode** for mono and depth images (`mono8`, `mono16`, `16UC1`, `32FC1`): Gradient between two colors, or a Turbo or Rainbow color map, over an automatic or fixed Value min/max.
- **Flip** horizontal and vertical, and **Rotation** 0/90/180/270°. Overlays follow the image.
- **Rectify** undistorts `plumb_bob` and `rational_polynomial` lenses on the GPU. Off by default.
- **Max FPS** now defaults to 15 for camera panels. Panels where you already chose a value keep it, and saved layouts are migrated automatically.

## Smooth under heavy robot data

Measured with a robot-sized load (4 raw 1280×720 cameras at 30 Hz, a 100,000-point lidar at 10 Hz, TF at 100 Hz, 50 log messages per second) in Chrome:

|                                   | 3.0.1 | 3.1.0 |
| --------------------------------- | ----- | ----- |
| CPU slowed 4×: long tasks in 20 s | 32–36 | 0     |
| CPU slowed 4×: worst frame        | 67 ms | 17 ms |
| Full speed: main thread busy      | 55 %  | 30 %  |

What changed:

- Images, point clouds and maps are decoded in **Web Workers**, which also convert raw images and scan point clouds; results move back without copying.
- **Frames a panel would skip are not decoded.** A camera drawn at 10 fps no longer decodes the other frames.
- **TF and path lines** no longer recompile a shader on every frame.
- **Point clouds** reuse their geometry instead of rebuilding it per message.
- **Log rows** are memoized, so only new lines render.
- **Panels hidden** behind an expanded panel do no render work.

The details and how to reproduce the numbers are in `docs/PERFORMANCE.md` (`scripts/heavy-bridge.js` and `scripts/perf-run.js`).

### On the robot

These changes remove the stutter caused by work in the browser. They cannot widen the network link: raw 1280×720 images are 2.8 MB a frame, so on Wi-Fi they still arrive late. Use the robot's `/compressed` image topics, or the **Prioritize robot motion** streaming mode in connection settings, to keep cameras and robot motion current.
