# MITI v3.3.5 — install with apt, run with `miti run`

## An apt package for Ubuntu

MITI now comes as a Debian package for Ubuntu 22.04 and 24.04, on amd64 (regular PCs) and arm64 (Jetson and other ARM computers). It carries its own Node.js, so nothing else is needed:

```bash
sudo apt install ./miti_3.3.5_amd64.deb     # or miti_3.3.5_arm64.deb, attached below
miti run                                    # http://<this machine>:3000; Ctrl+C stops it
```

- **Installing starts nothing.** `miti run` serves MITI in the terminal until Ctrl+C, with the same launcher as `pixi run miti`: a taken port moves to the next free one, and a foxglove_bridge already running is used.
- **`miti run --bridge`** also starts foxglove_bridge beside MITI from the ROS 2 in `/opt/ros` (`sudo apt install ros-humble-foxglove-bridge` or `ros-jazzy-...`). The ROS network section in the connection settings changes its `ROS_DOMAIN_ID` and robot address, as with `pixi run miti-bridge`.
- **Settings** are in `/etc/miti/miti.env` and `/etc/miti/bridge.env`; variables set in the shell win, e.g. `ROS_DOMAIN_ID=5 miti run --bridge`.
- **At boot instead:** `sudo systemctl enable --now miti` (and `miti-bridge`). Both services are off until enabled.

Both packages are tested on every change in clean Ubuntu 22.04 and 24.04 containers, each on a machine of its own architecture. Once the signed apt repository at `https://hiran-t.github.io/MITI` is online, `sudo apt-get install miti` and `apt upgrade` work too; see [docs/DEPLOYMENT.md](https://github.com/hiran-t/MITI/blob/main/docs/DEPLOYMENT.md#apt-package-ubuntu).

## Docker image

Releases now publish the MITI image to `ghcr.io/hiran-t/miti` (linux/amd64 and linux/arm64), so Docker users can run it without building:

```bash
docker run -d --restart unless-stopped -p 3000:3000 --name miti ghcr.io/hiran-t/miti:3.3.5
```

## Also

- `ros/foxglove-bridge.sh` uses the ROS 2 installed in `/opt/ros` when `ROS_DISTRO` is not set and Humble is not there.
