# MITI v3.2.1 — Documentation and bridge fixes

A maintenance release: the docs now match MITI 3.2, and the foxglove_bridge beside MITI handles a few more real-robot cases.

## foxglove_bridge beside MITI

- **nav2's `bond` messages are included**, so the `/bond` topic is offered instead of the bridge logging `package 'bond' not found` over and over. The robot's own message packages (for example `oc_g1_msgs`) still go in `ros/overlay/src`; see the deployment guide.
- **Port already in use**: the bridge now stops with a message saying so, and how to pick another port, instead of foxglove_bridge aborting with a bind error.
- **Discovery over Wi-Fi**: `ROS_STATIC_PEERS` (ROS 2 Jazzy) now reaches the bridge in Docker Compose, so it can find the robot by IP when Wi-Fi drops multicast discovery. Set it in `.env`.

## Documentation

- **README** in a standard layout: features, requirements, install and run (pixi, Docker Compose, from source), foxglove_bridge on the robot or beside MITI, configuration, using MITI, development, and troubleshooting.
- **Deployment guide** with install commands for pixi, Docker, Node.js and foxglove_bridge (`sudo apt install ros-<distro>-foxglove-bridge`), a systemd unit to run `pixi run miti` as a service, the bridge's settings, the robot's own messages and meshes, DDS tips, kiosk and offline installs, HTTPS, and troubleshooting.
- **API and architecture** docs match the current code: hooks, the bridge client and its decode workers, panels, types, and the deployment pieces.
- **Contributing, releases, security, 3D Scene, State Machine and performance** docs updated; issue and pull request templates ask for the ROS 2 distro and where foxglove_bridge runs.
