# MITI v3.3.0 — Windows support for pixi

MITI's pixi setup now runs on Windows 10 and 11 (x86-64), with the same commands as on Linux and macOS.

## Install pixi on Windows

```powershell
powershell -ExecutionPolicy ByPass -c "irm -useb https://pixi.sh/install.ps1 | iex"
```

## Run

```powershell
pixi run miti                    # MITI on http://<this machine>:3000
pixi run -e humble miti-bridge   # MITI and foxglove_bridge beside it (-e jazzy for Jazzy)
pixi run -e humble bridge        # foxglove_bridge only
pixi run -e humble build-msgs    # the robot's own message packages in ros/overlay/src
```

- pixi installs Node.js 22, and for the bridge ROS 2 and foxglove_bridge from RoboStack, for Windows; nothing else is installed system-wide.
- The bridge tasks use PowerShell versions of the scripts in `ros/` (`foxglove-bridge.ps1`, `miti-with-bridge.ps1`, `build-msgs.ps1`). They read the same settings (`ROS_DOMAIN_ID`, `RMW_IMPLEMENTATION`, `BRIDGE_PORT`, `BRIDGE_TOPIC_WHITELIST`, …), set with `$env:NAME = "value"` before `pixi run`.

## Windows notes

- **Firewall**: allow Node.js, Python and foxglove*bridge on private networks when Windows asks, or open TCP 3000 and 8765 and UDP 7400–7700 for DDS; keep the robot's network set to \_Private*. Commands are in the deployment guide.
- **The robot's own messages** need the Visual Studio 2022 Build Tools with the C++ workload (`winget install Microsoft.VisualStudio.2022.BuildTools ...`).
- **Start at login** with Task Scheduler (`schtasks /Create /TN MITI /SC ONLOGON ...`).
- **Docker Desktop** runs MITI but not the bridge profile, which needs Linux host networking. **WSL 2** works like Linux; for the bridge, turn on mirrored networking.

Windows support is new: the scripts were checked with PowerShell 7 and the packages resolve for Windows, but it has not yet been run on many Windows machines. Please report problems.

Details: [docs/DEPLOYMENT.md#windows](https://github.com/hiran-t/MITI/blob/main/docs/DEPLOYMENT.md#windows).
