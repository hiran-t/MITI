# MITI v3.3.4 — ROS network settings in the browser

## Change the ROS domain and robot address without a terminal

With foxglove_bridge running beside MITI (`pixi run -e humble miti-bridge` or `-e jazzy`), the connection settings (gear in the status bar) have a new **ROS network** section:

- **`ROS_DOMAIN_ID`** and **Robot IP addresses** (IPv4, comma-separated for several).
- **Apply and restart bridge** restarts foxglove_bridge with them; MITI reconnects on its own and the section shows when the bridge is running again.
- The settings are saved in `.miti/bridge.json` and used on the next start in place of the environment variables. Delete the file, or run `pixi run remove`, to go back to the environment.
- If the bridge stops after a change, MITI keeps running and the section shows the bridge's last log line, so the next try is one click away.

The page reaches the bridge through MITI's server (`/api/bridge`), which talks to the launcher on `127.0.0.1` with a token that changes on every start, and accepts only JSON. With Docker or a bridge on the robot, MITI does not own the bridge; the section then says where the settings belong.

## Finding the robot by IP on Humble

`ROS_STATIC_PEERS` (or the robot address set in MITI) now works on Humble as well as Jazzy, with pixi, on Windows and in Docker. The bridge scripts add the robot to Fast DDS's initial peers (a generated profile, unless `FASTRTPS_DEFAULT_PROFILES_FILE` is already set) or to Cyclone DDS's peers. Multicast discovery keeps working alongside, so this only helps on networks that drop multicast, such as Wi-Fi.
